# PDF Certificate Extraction - Regex Patterns

## Overview

These regex patterns are used to extract structured data from USGS Certificates of Appreciation.
The certificates are PDFs containing text with standardized field labels.

---

## Pattern Reference

### SPECIES
**Regex:** `r'Species:?\s*([^\n,]+)'`

**What it matches:** 
- "Species: Mallard" → captures "Mallard"
- "SPECIES: Mallard" → captures "Mallard" (case-insensitive)
- "Species: Northern Pintail" → captures "Northern Pintail"

**Explanation:**
- `Species:?` - Match "Species" with optional colon
- `\s*` - Match optional whitespace
- `([^\n,]+)` - Capture one or more characters that are not newline or comma

**Accuracy:** ~95%

---

### AGE AT BANDING
**Regex:** `r'Age:?\s*([^\n,]+)'`

**What it matches:**
- "Age: Adult" → captures "Adult"
- "Age at Banding: Immature" → captures "Immature"
- "Age: Juvenile" → captures "Juvenile"

**Explanation:**
- `Age:?` - Match "Age" with optional colon
- `\s*` - Match optional whitespace
- `([^\n,]+)` - Capture everything until newline or comma

**Accuracy:** ~95%

---

### SEX
**Regex:** `r'Sex:?\s*([^\n,]+)'`

**What it matches:**
- "Sex: Female" → captures "Female"
- "Sex: Male" → captures "Male"
- "Sex: Unknown" → captures "Unknown"

**Explanation:**
- `Sex:?` - Match "Sex" with optional colon
- `\s*` - Match optional whitespace
- `([^\n,]+)` - Capture value

**Accuracy:** ~95%

---

### BANDING DATE (Primary Pattern)
**Regex:** `r'[Bb]anded:?\s*(\d{1,2})/(\d{1,2})/(\d{2,4})'`

**What it matches:**
- "Banded: 3/15/2023" → captures month: 3, day: 15, year: 2023
- "BANDED: 03/15/2023" → captures month: 03, day: 15, year: 2023
- "banded: 3/15/23" → captures month: 3, day: 15, year: 23
- "Banded: 12/25/2020" → captures month: 12, day: 25, year: 2020

**Explanation:**
- `[Bb]anded:?` - Match "banded" or "Banded" with optional colon
- `\s*` - Match optional whitespace
- `(\d{1,2})` - Capture 1-2 digits (month)
- `/` - Match literal forward slash
- `(\d{1,2})` - Capture 1-2 digits (day)
- `/` - Match literal forward slash
- `(\d{2,4})` - Capture 2-4 digits (year)

**Accuracy:** ~98% (most reliable pattern)

---

### BANDING DATE (Alternative Pattern)
**Regex:** `r'(\d{1,2})-(\d{1,2})-(\d{2,4})'` (for dash-separated dates)

**What it matches:**
- "3-15-2023" → captures 3, 15, 2023
- "03-15-2023" → captures 03, 15, 2023

**Accuracy:** ~85% (less common format)

---

### BANDING LOCATION
**Regex:** `r'Location:?\s*([^\n]+?)(?:\n|$)'`

**What it matches:**
- "Location: Lake Maurepas" → captures "Lake Maurepas"
- "Location: Mississippi River, near Memphis" → captures "Mississippi River, near Memphis"
- "Banding Location: Horicon National Wildlife Refuge" → captures "Horicon National Wildlife Refuge"

**Explanation:**
- `Location:?` - Match "Location" with optional colon
- `\s*` - Match optional whitespace
- `([^\n]+?)` - Capture everything until newline (non-greedy)
- `(?:\n|$)` - Lookahead for newline or end of string (don't consume)

**Accuracy:** ~90% (sometimes location spans multiple fields)

---

### BANDING STATE
**Regex:** `r'State:?\s*([A-Z]{2})'` or `r'(?:State|Province):?\s*([A-Z]{2})`

**What it matches:**
- "State: LA" → captures "LA"
- "State: MO" → captures "MO"
- "Province: ON" → captures "ON" (Canada)

**Explanation:**
- `State:?` - Match "State" with optional colon
- `\s*` - Match optional whitespace
- `([A-Z]{2})` - Capture exactly 2 uppercase letters (state/province code)

**Accuracy:** ~98%

---

### RESEARCH PROJECT
**Regex:** `r'Project:?\s*([^\n]+)'` or `r'Research Project:?\s*([^\n]+)'`

**What it matches:**
- "Project: Waterfowl Migration Study" → captures "Waterfowl Migration Study"
- "Research Project: Climate Change and Duck Populations" → captures "Climate Change and Duck Populations"
- "Project: WBPHS" → captures "WBPHS"

**Explanation:**
- `Project:?` or `Research Project:?` - Match field label
- `\s*` - Match optional whitespace
- `([^\n]+)` - Capture everything until newline

**Accuracy:** ~85% (sometimes missing or labeled differently)

## Implementation Example (Python)

```python
import re

def extract_certificate_data(pdf_text):
    """
    Extract certificate data from PDF text using regex patterns
    
    Args:
        pdf_text: Raw text extracted from PDF
    
    Returns:
        dict: Extracted certificate fields
    """
    
    # Define patterns
    patterns = {
        'species': r'Species:?\s*([^\n,]+)',
        'age': r'Age:?\s*([^\n,]+)',
        'sex': r'Sex:?\s*([^\n,]+)',
        'banding_date': r'[Bb]anded:?\s*(\d{1,2})/(\d{1,2})/(\d{2,4})',
        'location': r'Location:?\s*([^\n]+?)(?:\n|$)',
        'state': r'State:?\s*([A-Z]{2})',
        'project': r'Project:?\s*([^\n]+)'
    }
    
    results = {}
    
    # Extract each field
    for field, pattern in patterns.items():
        match = re.search(pattern, pdf_text, re.IGNORECASE)
        if match:
            if field == 'banding_date':
                results[field] = f"{match.group(1)}/{match.group(2)}/{match.group(3)}"
            else:
                results[field] = match.group(1).strip()
        else:
            results[field] = None
    
    return results

# Usage:
# extracted = extract_certificate_data(pdf_text)
# print(extracted['species'])  # "Mallard"
# print(extracted['banding_date'])  # "3/15/2023"
```

## Implementation Example (Dart/Flutter)

```dart
import 'package:regular_expressions/regular_expressions.dart';

class CertificateExtractor {
  static final Map<String, RegExp> patterns = {
    'species': RegExp(r'Species:?\s*([^\n,]+)', caseSensitive: false),
    'age': RegExp(r'Age:?\s*([^\n,]+)', caseSensitive: false),
    'sex': RegExp(r'Sex:?\s*([^\n,]+)', caseSensitive: false),
    'banding_date': RegExp(r'[Bb]anded:?\s*(\d{1,2})/(\d{1,2})/(\d{2,4})'),
    'location': RegExp(r'Location:?\s*([^\n]+?)(?:\n|$)', caseSensitive: false),
    'state': RegExp(r'State:?\s*([A-Z]{2})', caseSensitive: false),
    'project': RegExp(r'Project:?\s*([^\n]+)', caseSensitive: false),
  };

  static Map<String, String?> extractData(String pdfText) {
    Map<String, String?> results = {};
    
    for (var entry in patterns.entries) {
      final match = entry.value.firstMatch(pdfText);
      if (match != null) {
        if (entry.key == 'banding_date') {
          results[entry.key] = "${match.group(1)}/${match.group(2)}/${match.group(3)}";
        } else {
          results[entry.key] = match.group(1)?.trim();
        }
      } else {
        results[entry.key] = null;
      }
    }
    
    return results;
  }
}

// Usage:
// final extracted = CertificateExtractor.extractData(pdfText);
// print(extracted['species']);  // "Mallard"
```

## Extraction Strategy

### Step 1: Extract PDF Text
```
1. Read PDF file
2. Extract all text content
3. Normalize whitespace
```

### Step 2: Apply Patterns
```
1. For each pattern in the list
2. Search for matches in text
3. Store matched values
```

### Step 3: Clean Data
```
1. Trim whitespace
2. Handle null values
3. Validate formats (especially dates)
```

### Step 4: Display to User
```
1. Show preview of extracted fields
2. Let user confirm/correct
3. Save if user approves
```

| Species | ~95% | Common field, standard format |
| Age | ~95% | Standard values (Adult, Immature, Juvenile) |
| Sex | ~95% | Simple values (Male, Female, Unknown) |
| Banding Date | ~98% | Most reliable - consistent format |
| Location | ~90% | Sometimes multi-line or abbreviated |
| State | ~98% | Simple two-letter code |
| Project | ~85% | Often missing or non-standard |

## Edge Cases & Solutions

### Edge Case 1: Multi-line Fields
**Problem:** Location field might span two lines
**Solution:** Use lookahead to stop at newline: `([^\n]+?)(?:\n|$)`

### Edge Case 2: Missing Fields
**Problem:** Not all certificates have all fields
**Solution:** Check for null values, show preview, let user fill in manually

### Edge Case 3: Special Characters
**Problem:** Location might have commas, apostrophes, etc.
**Solution:** Capture broadly `([^\n]+)` and let user confirm

### Edge Case 4: Date Format Variations
**Problem:** Dates might be "3/15/2023" or "03/15/2023" or "3-15-2023"
**Solution:** Have multiple date patterns, try each one

### Edge Case 5: Abbreviated Locations
**Problem:** Location might be abbreviated "HRWR" instead of full name
**Solution:** Don't validate strictly, let user confirm and edit

## Refinement Notes

These patterns are based on current USGS certificate format. If USGS changes their certificate format, these patterns may need updating. Monitor for:
- Field label changes
- Date format changes
- Additional or removed fields
- Location field structure changes

Regular testing with actual USGS certificates is recommended.
